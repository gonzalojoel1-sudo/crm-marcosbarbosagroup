# 🚨 INCIDENTE 2026-09-23 — CRM devuelve 500 en /crm/dashboard

## Síntoma

- `https://crm.marcosbarbosagroup.com/crm/dashboard` → **HTTP 500 Internal Server Error**
- También `/crm` y `/app` → 500
- Backend API funcionaba (`/api/method/ping` → 200)
- Widget `get_dashboard()` funcionaba vía Python

## Causa raíz

En `tabDefaultValue` (MariaDB) el key `__global:installed_apps` contenía `["frappe", "crm", "crm_core"]`.

El módulo `crm_core` no existía en `/home/frappe/frappe-bench/apps/` pero Frappe intentaba cargarlo al renderizar CUALQUIER página web (incluso el error page). El `get_app_path("crm_core", "www")` fallaba con `ModuleNotFoundError`.

Adicionalmente:
- `apps.json` (en sites/) tenía `crm_core` registrado (commit hash `a4c5a3c1091a732859a92596fa49f80e6b420dab`)
- `apps.txt` (en sites/) tenía `frappe / crm / crm_core`
- `tabInstalled Application` tenía un row con `app_name="crm_core"`
- `tabModule Def` tenía `MbCRM` con `app_name="crm_core"` y 18 DocTypes asignados

## Cómo se metió crm_core

Probablemente quedó de una instalación/instalación previa. `MbCRM` parece ser un módulo custom del usuario (Marcos Barbosa Group) que se asignó al app `crm_core` cuando ese app existía.

## Lo que arreglé

1. **`tabDefaultValue`**: `UPDATE` para cambiar `installed_apps` a `["frappe", "crm"]`
2. **`tabInstalled Application`**: `DELETE` del row con `app_name="crm_core"`
3. **`tabModule Def`**: `UPDATE app_name` de `MbCRM` de `crm_core` a `crm` (preserva el módulo custom)
4. **`tabDocType`**: `UPDATE module` de `MbCRM` a `FCRM` (módulo estándar del CRM, donde van DocTypes custom sin app específica)
5. **`apps.txt`**: removido `crm_core`
6. **`apps.json`**: regenerado solo con `frappe` y `crm`
7. **Redis cache**: `FLUSHDB` en `crm_redis-cache` para limpiar cache de installed_apps
8. **Backend restart**: `docker service update --force crm_backend`

## Migración de DocTypes custom

Los 18 DocTypes del usuario que vivían en `MbCRM`:
```
Account, Activity, CRM Emisor, CRM Factura, CRM Factura Item, CRM Pago,
CRM Pago Aplicacion, CRM Presupuesto, CRM Presupuesto Item, CRM Punto de Venta,
CRM Vertical, Deal, Event Attendee, GCal Connection, GCal Sync State,
Lead, Sync Conflict, Task
```

Estos NO se borraron — se reasignaron al módulo `FCRM` (módulo estándar del Frappe CRM para custom DocTypes). Mantienen todos sus fields y data.

## Lección

- El `installed_apps` global en `tabDefaultValue` es la fuente autoritativa para Frappe. `apps.txt` y `apps.json` son referencias, pero el DB manda.
- El cache de Redis debe limpiarse para que cambios en `installed_apps` se reflejen (FLUSHDB o `frappe.clear_cache()`).
- El render del error page falla si el `installed_apps` está corrupto, así que errores de fondo pueden presentarse como "Internal Server Error" sin pista clara.

## Si vuelve a pasar

1. `docker exec crm_mariadb mysql ... -e "SELECT * FROM tabDefaultValue WHERE defkey='installed_apps'"`
2. Si tiene app corrupta, `UPDATE tabDefaultValue SET defvalue='["frappe", "crm"]' WHERE defkey='installed_apps'`
3. `docker exec crm_redis-cache redis-cli FLUSHDB`
4. `docker service update --force crm_backend`
